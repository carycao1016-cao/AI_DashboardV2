# UI 前端工程规范

**英文原稿：** `docs/design/en/05_UI_Frontend_Engineering_Specification.md`

## 工程边界

前端只负责界面、状态展示和用户操作；AI、原始文件、数据库、密钥和发布权限留在服务端。所有请求通过兼容的 `/api/*` 接口，响应保持 `{ success, data, error }` 结构。

## 核心页面

- 项目列表与创建。
- 文件上传和版本管理。
- 识别进度与 Sheet 摘要。
- Review 工作区与 Data Explorer。
- Dashboard Draft 与发布门禁。
- Client View 和分享链接。
- Admin 配置、审计和备份恢复。

## 状态与错误

必须区分上传中、扫描中、AI 处理中、验证中、后台继续处理、Review required、失败、已发布和回滚。前端轮询超时只表示当前界面等待时间结束，不得把服务端任务标记为失败。

失败记录和质量风险记录必须在 Review 中可见；人工 Review 保存是最终确认。

## 数据显示

展示值优先使用经验证的 Excel display value；结构化计算使用 parsed value 和 parsed unit；`-`、不可用和 0 必须视觉上可区分。显著性只展示官方且已映射的标记，不推断方向。

## UI 基线

使用一致的 Kantar 视觉系统、响应式布局、键盘可操作控件、明确焦点、可读对比度和加载/空/错误状态。复杂表格必须支持 Sheet、表名、题号、指标、Header 和来源位置的扫描。
