# UX 流程与原型规范

**英文原稿：** `docs/design/en/03_UX_Flow_and_Prototype_Specification_v1.1.md`

## 核心流程

上传文件 -> 扫描中 -> 识别摘要 -> 异常 Review -> Dashboard Draft -> Creator 调整 -> 发布 -> Client 查看。

识别过程必须显示当前阶段、Sheet 数量、物理表数量、异常数量和可继续处理状态。前端超时不等于任务失败，应显示“后台仍在处理”，并继续显示任务进度。

## Creator 工作区

- 文件上传区：支持 Excel/CSV、编码提示和文件版本。
- 识别摘要：按 Sheet 展示 `complete`、`needs_more_context`、`ambiguous`、`not_a_table`。
- Review：展示表范围、Title、Header、Base、数据、显著性和来源单元格。
- Data Explorer：允许查看原始展示值、解析值、单位、可用状态和 Lineage。
- Dashboard Draft：发布前只能展示已通过验证的结果。

## 编辑边界

Creator 可以修订题号、题文、表名、翻译、Header 显示名和映射；保存即视为人工最终确认。自动质检不得再次拦截明确的 Review 保存，但仍保留授权、并发、校验和审计。

原始数值、源单元格、物理范围和官方显著性来源不可通过普通文案编辑伪造。缺失 Base 不显示，`-` 不转换为 0。

## Client View

Client 只能看到已发布内容、允许的 Filter、Base、指标和官方显著性。未映射显著性、来源冲突和未解析值不得显示为统计结论。

## 响应式与可访问性

桌面、平板和移动端均需保持侧栏、主工作区、Review 抽屉和表格可读；关键状态不能只依靠颜色；加载、空状态、错误、权限和后台处理中状态都必须有明确文案。
