# 验证与验收测试计划

**英文原稿：** `docs/design/en/04_Validation_and_Acceptance_Test_Plan.md`

## 验证层次

1. 单元测试：JSON 枚举、值单位、可用状态、显著性映射、来源 Lineage。
2. Parser 测试：Sheet 扫描、边界、Header、Base、Count/Percentage、CSV 编码。
3. Golden 测试：针对物理表标注比较最终 Python 结构。
4. 端到端测试：上传、识别、Review、Draft、发布、查看和回滚。

## Golden 门槛

- Layer 1 覆盖率 100%，不得漏表。
- Layer 2 最终结构准确率至少 95%。
- 错误自动接受为 0。
- `review_required` 不超过 10%。
- 每张物理表包含 3-5 个 Cell Truth：Base、普通值、显著性和异常值（如存在）。

## 必测场景

- Quantum 普通表、交替 Count/Percentage 表、下一行显著性。
- Decipher Count、Percentage、相邻列显著性和多 Sheet 变体。
- 同单元格 `20%A`、`20ABC`、`20%ABC`。
- 1-3 层 Header、超过三层 Header、合并/未合并 Header。
- 缺失 Base、空白、`-`、`<1%`、`*`、`**`、数字 0。
- 题文不在 A 列、`#page`、Index/Summary `not_a_table`。
- UTF-8、GB18030、GBK、Big5 和低置信度 CSV。

## 发布验收

每个可发布值必须有源单元格、解析单位、可用状态和 Lineage；未解决的范围、Header、显著性或变体冲突必须排除并生成报告。
